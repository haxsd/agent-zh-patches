# 原理

这个仓库只做一件事：**把桌面应用里写死在打包 JS 中的界面文案换成中文，并且可验证、可回退**。难点不在翻译，而在「只改该改的地方」。

## 为什么不能全局替换

打包产物里，`"Settings"` 既可能是按钮文字，也可能是命令 id、CSS 类名、事件名、枚举值。全局替换会改坏逻辑。
所以流程是**先扫描、再按记录的位置替换**：

1. **扫描**：解析 JS 字面量，只保留「作为 UI 属性值」出现的那些——`label`、`title`、`children`、`placeholder`、
   `description`、`tooltip` 等（完整白名单见 `apps/<app>/rules.json` 的 `uiProps` / `uiPropSuffixes`）。
2. **记录位置**：每个候选记录它在文件中的**字节区间**（不是模糊匹配），以及属性类型、是否同时出现在风险位置。
3. **分级**：
   - `auto`：所有出现位置都是 UI，可以全部替换；
   - `context`：既在 UI 又在别处，只在记录的 UI 区间替换；
   - `skip`：命中代码标识符、事件名、颜色值、URL 等，不替换（确认是界面文案的，列进 `promote` 强制按位置替换）。
4. **替换**：只改记录过的区间，不搜索、不猜测。替换后跑 `node --check` 做语法校验。
5. **审计**：重新扫描落盘后的文件，逐字面量核对「原文出现次数 = 原次数 − 替换次数」「译文出现次数 = 替换次数」。
   任何越界都会暴露出来。
6. **校验值**：VS Code 系应用会在 `product.json` 的 `checksums` 里记录核心包的哈希，替换后必须同步，
   否则应用拒绝加载或回退。

## 安全门禁

- 版本或文件大小与扫描快照不一致 → 拒绝写盘（防止应用在扫描与写盘之间自动升级，把旧坐标套到新文件上）。
- 写回 `product.json` 前复核版本号，避免把旧值写到新安装上。
- 每次写盘前把原文件 gzip 备份到数据目录，`restore` 一条命令还原。
- 语法校验不过 → 中止，原文件不动。

## 为什么译文不进仓库

译文来自闭源安装包里的字符串。公开发布等于分发厂商内容，所以：

- 仓库只有引擎、适配层、规则、版本矩阵；
- 译文由用户的 agent 在本地生成，存在数据目录；
- 维护者自己的预置译文放在私有仓库，用 `--data` 指向。

## 多应用适配

应用差异全部收敛在 `apps/<app>/adapter.json`：

- 安装位置与版本读取方式；
- 目标文件列表（哪些 bundle 要处理）；
- 校验值所在文件与键前缀；
- 规则文件（UI 属性白名单、长度限制）。

引擎本身不认识 Cursor 或 Devin。新增应用 = 新增一个 adapter + 跑通一次 `scan → apply → audit`。
